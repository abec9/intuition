# Тестирование и ревью

## Основные команды

Запуск автоматических тестов:

```sh
npm test
```

Проверка каталога профессий:

```sh
npm run review:professions
```

## Что покрывают тесты

| Файл | Что проверяет |
|---|---|
| `tests/game.test.mjs` | Раунды, лимиты вопросов, исключения, финал, очистку ответов. |
| `tests/dialogue-pipeline.test.mjs` | AI-цепочку, прямые догадки, утечки, ремонт ответа, отмену. |
| `tests/server-catalog.test.mjs` | HTTP-сценарий с каталогом и тестовой моделью. |
| `tests/catalog-data.test.mjs` | Структуру и качество текущего каталога. |
| `tests/profession-catalog.test.mjs` | Загрузку, валидацию и выбор профессий. |
| `tests/catalog-game.test.mjs` | Сборку партии из каталога. |
| `tests/session-memory.test.mjs` | Ротацию портретов и очистку после трёх партий. |
| `tests/identity.test.mjs` | Соответствие имён полу портрета. |
| `tests/llm.test.mjs` | Подключение к LM Studio и ошибки генерации. |

HTTP-тесты используют тестовый сервер модели и временный каталог. Они не зависят от реальной LM Studio и не портят пользовательский `professions.json`.

## Ревью профессий

`catalog-review.mjs` проверяет каталог без обращения к модели. Он выдаёт Markdown-отчёт и код завершения:

- `0` — автоматических ошибок нет;
- `1` — есть ошибки структуры или утечки.

Текущий каталог: 50 профессий, 0 ошибок, 0 замечаний.

## Ревью диалогов

Отчёты по диалогам лежат в `review/`. Самый важный для текущей защиты:

```text
review/semantic-disclosure-check.json
```

Скрипт воспроизведения:

```sh
node review/check-semantic-disclosure.mjs
```

Эти проверки нужны для случаев, где персонаж раньше выдавал себя через отрицание: например, говорил, что «не учит детей», хотя искомая профессия была учителем.

Для баланса после живых партий используется отдельный прогон:

```sh
node review/check-balance.mjs
```

Он запускает локальную модель на фиксированном составе профессий из проблемной партии и проверяет, что ответы стали полезнее для сравнения версий: персонаж держит в голове настоящую профессию, не выдаёт её напрямую, а сила косвенной зацепки растёт по турам. Отчёты сохраняются в `review/balance-live.json`, `review/balance-final.json` и `review/balance-extraction.json`.

## Как добавлять новые проверки по логам

1. Найти плохой вопрос и плохой ответ в логе.
2. Определить, что именно раскрыто: подтверждение, отрицание, уникальная обязанность, ложный факт.
3. Добавить кейс в тест `dialogue-pipeline.test.mjs` или отдельный скрипт в `review/`.
4. Проверить, что плохая реплика отклоняется.
5. Проверить, что нормальная близкая реплика всё ещё проходит.

Важно добавлять рядом положительный пример. Иначе фильтр может стать слишком строгим, и персонажи начнут отвечать одинаковыми отказами.

## Что тесты не доказывают

Тесты не гарантируют, что любая локальная модель будет вести себя идеально. Они доказывают правила кода, обработку известных опасных ситуаций и формат ответов. Живая модель всё равно может ошибиться, особенно на косвенных вопросах, длинной истории или слабом русском.
