# Диагностика

## «Модель сейчас недоступна»

Что проверить:

1. В LM Studio включён Local Server.
2. Загружена именно разговорная модель, не embeddings.
3. Адрес совпадает с `LLM_BASE_URL`.
4. Компьютер с Node.js видит адрес LM Studio.

Проверка из браузера игры:

```text
http://127.0.0.1:4173/api/status
```

Ожидаемый результат:

```json
{"connected":true,"model":"..."}
```

Если модель на другом адресе:

```sh
LLM_BASE_URL='http://127.0.0.1:1234' npm start
```

## «История пока не готова»

Чаще всего причина в `professions.json`:

- файл ещё дописывается;
- JSON оборван;
- не хватает обязательных полей;
- профессий меньше шести;
- возрастные ограничения не подходят выбранным портретам.

Запусти:

```sh
npm run review:professions
```

Если старая партия была успешной, сервер сохраняет её до успешного создания новой.

## Вопрос не отправляется

Проверь:

- выбран ли персонаж;
- не закончился ли лимит вопросов текущего раунда;
- персонаж не исключён;
- не ждёт ли игра ответ на прошлый вопрос;
- нет ли ошибки модели внизу панели.

Если ответ модели не прошёл проверку, вопрос не списывается. Можно повторить или задать иначе.

## «Ответ модели оборвался»

Игра считает ответ оборванным, когда LM Studio возвращает `finish_reason: "length"`. Один такой сбой теперь обрабатывается внутри сервера: этап повторяется автоматически с большим лимитом, и игрок не видит ошибку.

Если сообщение всё равно появилось, значит один и тот же этап оборвался два раза подряд. Вопрос не списан. Обычно помогает перезадать вопрос короче, проверить контекстное окно модели или загрузить модель, которая стабильнее возвращает русский JSON.

## Персонаж говорит слишком медленно

Нормальный путь занимает три локальных запроса. Если ответ отклоняется, будет до пяти запросов.

Что помогает:

- более быстрая локальная модель;
- меньше параллельных игроков;
- закрыть другие тяжёлые задачи на компьютере;
- проверить, что LM Studio не выгружает модель;
- использовать модель, которая хорошо держит русский и JSON.

## Персонаж всё равно выдал профессию

Сохрани:

- профессию в заголовке;
- имя персонажа;
- вопрос;
- ответ;
- предыдущие реплики этого персонажа.

Затем нужно превратить случай в тест или replay-скрипт в `review/`. Для защиты важны реальные формулировки игрока, потому что косвенная утечка часто держится на контексте.

## Друзья не могут открыть ссылку

Если игра в одной сети:

- сервер должен быть запущен на `HOST=0.0.0.0`;
- порт должен быть виден в локальной сети;
- устройства должны быть в одной сети;
- гостевая Wi-Fi сеть часто блокирует доступ;
- macOS может попросить разрешить входящие соединения.

Если игра через туннель:

- `PUBLIC_ORIGIN` должен точно совпадать с публичным HTTPS-адресом;
- сервер нужно перезапустить после смены адреса туннеля;
- оба окна, туннель и сервер, должны работать одновременно.

## После перезапуска пропала партия

Это ожидаемо. Сервер хранит партии в памяти процесса Node.js. Постоянной базы данных сейчас нет.

## В двух вкладках одна партия

Это ожидаемо для одного браузера: обе вкладки используют одну cookie-сессию. Для отдельной партии открой приватное окно или другой браузер.
