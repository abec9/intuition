# HTTP API

Сервер отдаёт HTML/CSS/JS из `public/` и JSON API под `/api/`.

## Общие правила POST-запросов

Для POST нужны:

```http
Content-Type: application/json
X-Intuition-Client: 1
```

`Origin` должен быть разрешён сервером. Разрешённые origin строятся из `HOST`, `PORT` и `PUBLIC_ORIGIN`.

Тело запроса ограничено 8192 байтами.

## `GET /api/status`

Проверяет доступность LM Studio. Сессию игры не создаёт.

Пример ответа:

```json
{
  "connected": true,
  "model": "google/gemma-4-12b"
}
```

Если модель недоступна:

```json
{
  "connected": false,
  "model": null
}
```

## `GET /api/game`

Возвращает публичное состояние текущей сессии. Если партии ещё нет, вернётся пустое состояние.

Ключевые поля:

| Поле | Смысл |
|---|---|
| `id` | ID партии или `null`. |
| `title` | Название сцены. |
| `setting` | Описание места встречи. |
| `targetProfession` | Профессия, которую ищет игрок. |
| `professionPool` | Перемешанный список шести профессий текущей партии без привязки к персонажам. |
| `questionLimit` | Лимит вопросов текущего раунда. |
| `round` | Номер раунда. |
| `questions` | Сколько вопросов уже задано в раунде. |
| `finished` | Завершена ли партия. |
| `busy` | Генерируется ли сейчас ответ персонажа. |
| `preparing` | Готовится ли новая партия. |
| `generationError` | Ошибка подготовки партии, если была. |
| `characters` | Публичные карточки персонажей. |
| `history` | История вопросов и ответов. |
| `eliminated` | ID исключённых персонажей. |
| `result` | Финальный результат или `null`. |

До завершения партии активные карточки в `characters` не содержат `profession` и `clue`. Исключённые карточки получают только `profession`; `clue` появляется у всех карточек после завершения партии. Профессии партии видны общим списком в `professionPool`.

## `POST /api/game/new`

Создаёт новую партию асинхронно.

Тело:

```json
{}
```

Ответ: `202` и текущее состояние. Пока партия готовится, `preparing` будет `true`.

Если текущая игра ждёт ответ персонажа, сервер вернёт ошибку и попросит дождаться ответа.

## `POST /api/ask`

Задаёт вопрос персонажу.

Тело:

```json
{
  "gameId": "uuid-партии",
  "requestId": "стабильный-id-запроса",
  "characterId": "person-12",
  "question": "Что тебя больше всего утомляет?"
}
```

Ограничения:

- `question` должен быть строкой от 1 до 600 символов после обрезки пробелов;
- персонаж должен существовать и не быть исключён;
- партия не должна быть завершена;
- лимит вопросов раунда не должен быть исчерпан;
- игра не должна быть занята другим ответом.

Если модель не ответила, ответ оборвался или проверка секрета не прошла, вопрос не списывается.

## `POST /api/eliminate`

Исключает персонажа.

Тело:

```json
{
  "gameId": "uuid-партии",
  "requestId": "стабильный-id-запроса",
  "characterId": "person-12"
}
```

Если в этот момент генерируется ответ, сервер отменит генерацию и не запишет поздний ответ в историю.

После исключения:

- если исключён носитель искомой профессии, `finished` сразу становится `true`;
- если исключён другой персонаж, его карточка получает `profession`, а если осталось больше одного человека, начинается следующий раунд;
- если остался один человек, `finished` становится `true`.

## Ошибки

Ошибки возвращаются как JSON:

```json
{"error":"Текст ошибки"}
```

Частые статусы:

| Статус | Когда бывает |
|---:|---|
| 400 | Плохой JSON, слишком длинный запрос, неверный вопрос. |
| 403 | Неразрешённый host/origin или запрос не из игры. |
| 404 | Неизвестный API route или статический файл. |
| 409 | Игровое действие сейчас невозможно. |
| 413 | Тело запроса больше 8192 байт. |
| 502 | Модель не смогла подготовить ответ. |
| 503 | Слишком много открытых сессий. |

## Идемпотентность `requestId`

Успешные мутации сохраняются в `game.receipts`. Повтор того же `requestId` с теми же данными вернёт сохранённое состояние. Повтор того же `requestId` с другими данными вернёт ошибку.

Браузер использует это для безопасного повтора сетевых запросов.
