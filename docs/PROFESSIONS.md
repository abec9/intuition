# Каталог профессий

## Назначение

`professions.json` задаёт современные профессии, из которых сервер собирает партии. Сейчас в каталоге 50 профессий:

- 15 простых;
- 25 средних;
- 10 сложных.

Автоматическое ревью текущего файла проходит без ошибок и замечаний. Описания профессий имеют длину от 700 до 791 символа, стили ответов — от 424 до 459 символов.

## Где находится файл

```text
/Volumes/WD2TB/Projects/games/intuition/professions.json
```

Можно указать другой файл:

```sh
PROFESSIONS_FILE='/путь/к/professions.json' npm start
```

Справочник не лежит в `public/`, поэтому браузер не может скачать его напрямую.

## Минимальная структура

```json
{
  "version": 1,
  "professions": [
    {
      "id": "software_developer",
      "title": "Программист",
      "difficulty": "easy",
      "description": "...",
      "answerStyle": "...",
      "psychologicalTrace": ["..."],
      "forbiddenWords": ["..."],
      "forbiddenTopics": ["..."],
      "softHints": ["..."],
      "goodAnswers": ["..."],
      "badAnswers": ["..."],
      "directQuestionEvasion": ["..."],
      "tooObviousSignals": ["..."],
      "aliases": ["..."],
      "minAge": 18,
      "maxAge": 120
    }
  ]
}
```

## Поля профессии

| Поле | Для чего нужно |
|---|---|
| `id` | Стабильный технический идентификатор в `latin_snake_case`. |
| `title` | Название профессии, которое видит игрок. |
| `difficulty` | Сложность: `easy`, `medium`, `hard`. |
| `description` | Подробное описание работы и обязанностей. |
| `answerStyle` | Как человек этой профессии обычно может звучать в разговоре. |
| `psychologicalTrace` | Черты внимания и мышления, которые профессия могла оставить. |
| `forbiddenWords` | Слова и термины, которые слишком прямо раскрывают профессию. |
| `forbiddenTopics` | Темы, которые опасны для ответа. |
| `softHints` | Мягкие психологические подсказки без прямых рабочих деталей. |
| `goodAnswers` | Примеры допустимых косвенных ответов. |
| `badAnswers` | Примеры слишком очевидных или запрещённых ответов. |
| `directQuestionEvasion` | Примеры уклонения от прямой догадки. |
| `tooObviousSignals` | Признаки, по которым редактору легче увидеть утечку. |
| `aliases` | Синонимы и варианты названия профессии. |
| `minAge`, `maxAge` | Необязательные возрастные ограничения для назначения роли. |

## Редакционные требования

`professions.schema.json` задаёт строгий формат для полноценного каталога:

| Поле | Требование |
|---|---|
| `professions` | ровно 50 записей |
| `description` | 500–900 символов |
| `answerStyle` | 300–600 символов |
| `psychologicalTrace` | 6–10 пунктов |
| `forbiddenWords` | 12–25 пунктов |
| `forbiddenTopics` | 6–10 пунктов |
| `softHints` | 12–18 пунктов |
| `goodAnswers` | 8–12 пунктов |
| `badAnswers` | 8–12 пунктов |
| `directQuestionEvasion` | 5–8 пунктов |
| `tooObviousSignals` | 8–15 пунктов |

Загрузчик игры мягче схемы: для тестовой партии ему достаточно хотя бы шести валидных профессий и минимум трёх `softHints` у каждой. Но для нормальной версии игры нужно держать полный редакционный формат.

## Как выбираются профессии

При новой партии сервер:

1. читает файл;
2. проверяет структуру;
3. выбирает шесть профессий;
4. старается не брать профессии из прошлой партии;
5. назначает их выбранным портретам;
6. проверяет возрастные ограничения;
7. выбирает целевую профессию.

Если возрастные ограничения не позволяют назначить шесть профессий выбранным людям, сервер вернёт ошибку каталога.

## Что считается хорошей профессией

Хорошая запись даёт модели материал для живого ответа, но не толкает её к очевидной выдаче. Описание профессии должно быть современным, конкретным и правдоподобным. Подсказки должны быть человеческими: отношение к ошибкам, ответственности, доверию, вниманию, срокам, конфликтам.

Плохая запись строится вокруг предметов и прямых обязанностей. Например, если все подсказки архитектора говорят про чертежи, планировки, стройку и заказчика, игрок быстро угадает роль. Лучше писать про привычку держать в голове ограничения, видеть слабые места идеи, терпеть долгие согласования и спорить с хаосом.

## Проверка каталога

Основная команда:

```sh
npm run review:professions
```

Проверка другого файла:

```sh
npm run review:professions -- /путь/к/professions.json /путь/к/PROFESSIONS-REVIEW.md
```

Автопроверка ловит:

- неправильное количество профессий;
- неверный `id`;
- повторы;
- неверное распределение сложности;
- слишком короткие или длинные поля;
- слишком мало пунктов в массивах;
- утечки в `softHints`, `goodAnswers`, `directQuestionEvasion`;
- слишком общие запретные слова;
- повторы подсказок.

Автопроверка не умеет полностью оценить литературное качество, современность профессий и тонкость намёков. После неё нужно читать каталог как редактор.

## Что делать, если файл дописывает локальная модель

Пока модель пишет `professions.json`, файл может быть оборванным. Сервер в этом случае покажет ошибку:

```text
professions.json содержит некорректный или оборванный JSON.
```

Нужно дождаться окончания записи и повторить создание партии. Старую успешную партию сервер при такой ошибке сохраняет.
