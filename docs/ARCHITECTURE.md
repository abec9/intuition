# Архитектура проекта

## Общая схема

```text
Браузер
  |
  | HTTP JSON + статические файлы
  v
Node.js server.mjs
  |
  | /v1/chat/completions и /api/v0/models
  v
LM Studio с локальной моделью
```

Сервер отвечает за правила игры, сессии, выбор портретов, назначение профессий, валидацию и отмену запросов. Браузер отвечает за интерфейс, но не хранит секреты профессий.

## Основные файлы

| Файл | Роль |
|---|---|
| `server.mjs` | HTTP-сервер, сессии, API, раздача интерфейса. |
| `game.mjs` | Правила партии: вопросы, раунды, исключения, финал, публичное состояние. |
| `llm.mjs` | Подключение к LM Studio и вызовы модели. |
| `dialogue-pipeline.mjs` | Семантическая цепочка ответа персонажа и AI-ревью. |
| `dialogue.mjs` | Личная память персонажа и выбор разрешённых мягких подсказок. |
| `catalog-scenario.mjs` | Сборка новой партии из каталога профессий и портретов. |
| `profession-catalog.mjs` | Загрузка и базовая валидация `professions.json`. |
| `catalog-review.mjs` | Редакционная проверка качества каталога. |
| `profession-rules.mjs` | Словари, запреты, распознавание профессиональных догадок. |
| `portraits.mjs` | 36 портретных слотов и ротация портретов. |
| `characters.mjs` | 36 постоянных карточек людей с именами и портретами. |
| `session-memory.mjs` | Межигровая память и очистка после трёх партий. |
| `public/app.js` | Браузерная логика интерфейса. |
| `public/index.html` | Разметка игры. |
| `public/style.css` | Визуальный стиль игры. |
| `professions.json` | Каталог из 50 профессий. |
| `professions.schema.json` | Редакционная JSON Schema каталога. |

## Создание новой партии

1. Браузер отправляет `POST /api/game/new`.
2. Сервер выбирает шесть портретов из 36.
3. Сервер читает `professions.json`.
4. Из каталога выбираются шесть профессий.
5. Профессии назначаются выбранным людям с учётом `minAge` и `maxAge`.
6. Выбирается цель партии.
7. Браузер периодически читает `GET /api/game`, пока `preparing` не станет `false`.

Локальная модель на этом этапе не вызывается. Это сознательно ускоряет старт партии и убирает риск оборванного JSON-сценария.

## Выбор профессий и портретов

Портреты берутся из шести спрайтовых листов:

- `public/portraits.png`;
- `public/portraits-2.png`;
- `public/portraits-3.png`;
- `public/portraits-4.png`;
- `public/portraits-5.png`;
- `public/portraits-6.png`.

Всего 36 слотов: мужчины и женщины разного возраста от 22 до 72 лет. Имена, возраст и пол карточек заданы в `characters.mjs`, поэтому «Максим Андреевич» не окажется бабушкой: имя и портрет связаны заранее.

При создании новой партии сервер старается не повторять недавно использованные портреты. Если доступных портретов меньше шести, он избегает только портретов прошлой партии.

## Игровое состояние

В памяти партии хранится:

- `id`;
- номер раунда;
- сколько вопросов задано в текущем раунде;
- список исключённых персонажей;
- история вопросов и ответов;
- шесть приватных персонажей с профессиями;
- целевой персонаж и целевая профессия;
- перемешанный публичный список профессий партии без привязки к персонажам;
- словарь профессий для фильтров;
- карта обработанных `requestId`.

Публичное состояние отдаётся через `publicState()`. До завершения партии активные карточки не раскрывают профессию, исключённые карточки раскрывают только название профессии, а приватные описания остаются скрытыми. Общий список профессий партии отдаётся отдельно в `professionPool`.

## Отмена ответа при исключении

Когда игрок задаёт вопрос, сервер создаёт `AbortController` и помечает игру как занятую. Если игрок исключает персонажа во время генерации, `eliminate()` вызывает `abort()`, снимает флаг занятости и переводит игру дальше.

Если модель всё же вернёт ответ после отмены, `ask()` проверит, что активный `pending` уже не тот, и не запишет ответ в историю.

## Идемпотентность действий

Для `POST /api/ask` и `POST /api/eliminate` браузер отправляет `requestId`. Сервер запоминает успешный ответ для этого `requestId`.

Если браузер повторил тот же запрос с теми же данными, сервер вернёт сохранённое состояние. Если тот же `requestId` использован с другими данными, сервер вернёт ошибку.

Это защищает от двойного списания при повторе сетевого запроса после успешной обработки.

## Безопасность в текущем смысле

Сервер проверяет:

- `Host`;
- `Origin` для POST-запросов;
- заголовок `X-Intuition-Client: 1`;
- `Content-Type: application/json`;
- размер JSON-тела до 8192 байт;
- совпадение `gameId`;
- корректность `requestId`.

Это защита для локальной игры и домашней сети. В проекте нет аккаунтов, авторизации игроков, TLS, постоянной базы данных и промышленного ограничения частоты запросов.

## Что хранится на диске

На диске лежат код, портреты, каталог профессий, тесты и отчёты ревью. Активные партии на диск не сохраняются.

`professions.json` читается перед новой партией. Уже начатая партия сохраняет копию выбранных профессий в памяти и не меняется при редактировании файла.
